# 图书馆阅读挑战系统

按年龄段发布阅读挑战：家长为孩子报名、提交阅读记录，馆员核对借阅与完成情况，
达标后发放实体纪念章的预约领取凭证。纯 Python 标准库实现（`http.server` + `sqlite3`），零依赖。

## 启动

```bash
python3 app.py            # 首次自动建库、生成封面示意图并灌入演示数据
python3 app.py --reset    # 重建演示数据
python3 app.py --port 8080
```

打开 http://127.0.0.1:8000 ，从首页进入三端：

- **孩子端**：书封面墙 + 进度条，已核验的书盖绿色标记，完成后显示领取凭证码
- **家长端**：待核验项汇总、提交/修改阅读记录（每次修改留版本）、凭证与候补位置
- **馆员端**：待核验队列（清楚区分「已借阅」与「已提交·借阅未同步」）、达标审核、
  库存与候补、借阅同步、凭证核销、活动配置（新建活动 / 中途换书目 / 新增图书）

## 测试

```bash
python3 -m unittest discover -s tests
```

覆盖：同一本书重复计数、年龄边界（含活动中跨年龄组）、借阅晚同步、审核回避、
库存并发竞争（两个馆员同时核验不重复发章）、记录版本历史、中途换书目、候补按达标时间。

## 演示数据包含的案例

- **重复书目**：小明对《月亮晚安》提交了两次，第二次标记「重复提交·不计数」
- **补录 + 借阅晚同步**：小明的《太空种子》是补录记录，借阅事件仍在适配器发件箱，
  馆员点「同步借阅数据」后记录自动从「借阅未同步」变为可核验
- **审核回避**：馆员陈静是小雨的家长，审核小雨的记录/达标会被拒绝
- **库存竞争与候补**：成长挑战纪念章库存仅 1 枚；小雨、小明先后达标，
  先达标者发章，后来者按达标时间进候补，补货后按序发放
- **中途换书目**：成长挑战的书目有两个版本（《太空种子》→《海的来信》），
  记录按阅读日期当天生效的版本判定

## 架构

```
app.py               入口：建库、灌种子、起服务
reading/
  db.py              SQLite schema（WAL、外键、唯一约束）与 BEGIN IMMEDIATE 事务
  services.py        领域逻辑：报名/记录/去重/版本/借阅核对/达标审核/库存候补
  adapters.py        模拟适配器：借阅系统（发件箱延迟同步）、提醒通知
  seed.py            演示数据 + 本地 SVG 封面示意图生成
  web.py             服务端渲染三端界面（白 / 藏青 / 克制的绿）
tests/test_reading.py
data/reading.db      运行时生成
static/covers/       运行时生成的封面示意图
```

关键设计：

- **去重**：同一报名下同一本书已有有效记录时，新记录标记 `duplicate` 不计进度；
  进度始终按 `COUNT(DISTINCT book_id)` 计算；被驳回后可重新提交
- **版本**：记录每次修改写入 `record_versions`；已核验记录被修改后回到待核验，
  旧核验结论作废
- **晚同步**：借阅事件带 `visible_after`，同步后才可见；同步时自动重评
  `pending_borrow` 记录
- **年龄**：按报名当天计算并快照到报名记录，活动中跨年龄组不影响本次参与
- **换书目**：书目按版本生效，记录按 `read_date` 当天的版本判定
- **并发发章**：`BEGIN IMMEDIATE` 串行化 + 报名状态条件翻转（rowcount 校验）
  + `inventory` 条件扣减（`issued < total`）+ 唯一约束兜底；库存不足按
  `achieved_at` 进候补，补货按序发放
- **回避**：馆员可关联家长身份，核验与达标审核均拒绝本人子女
